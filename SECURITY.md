# Security Policy

## Reporting a vulnerability
Do not publish exploitable vulnerability details in a public issue. Use GitHub Private vulnerability reporting for this repository if enabled. If unavailable, open a minimal public issue asking for a private reporting route; do not include exploit details, credentials, or personal data.

No dedicated security email address is configured here. Do not guess an address.

## Supported versions
No browser release exists yet. List supported versions after releases begin.

## Response expectations
A response-time SLA has not yet been committed. Before production release, define a monitored reporting channel, triage owner, severity criteria, disclosure process, and remediation targets.

Do not test against other people's devices, accounts, or services without permission.
